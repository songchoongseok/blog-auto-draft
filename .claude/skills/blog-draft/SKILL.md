# 네이버 블로그 임시글 작성 (중간 원고 → 네이버 임시저장 → 완료 정리)

## 대상 고르기 (2026-11-08 기준: 한 번에 한 건)

- 사용자는 **한 번에 한 건만** 넣는다. 하위 폴더를 만들지 않고 `inputs/` 바로 아래에 `topic.md` 1개 + 사진 n장을 둔다.
- `inputs/topic.md`는 항상 빈 양식으로 준비돼 있다(C에서 다시 만든다). 없으면 `cp templates/topic.md inputs/topic.md`로 만든다.
- `topic.md`가 빈 양식 그대로이고(제목·주제·경험이 비어 있음) 사진도 없으면 "신규 건 없음"이라고 알리고 끝낸다.
- `inputs/` 아래에 예전 방식의 하위 폴더가 남아 있으면 그 폴더도 한 건으로 보고 같은 방법으로 처리한다.

## 폴더 구조

```
inputs/                  신규 입력: topic.md 1개 + 사진 n장 (+ Claude가 쓰는 result.md)
drafts/                  중간 원고 (draft.md, images/) — 임시저장 전까지 여기 남는다
done/<제목>/              완료: topic.md + 원본 사진 + draft.md (한 폴더에)
```

- `<제목>`은 `topic.md`의 `title`을 그대로 쓴다(날짜·번호 없이). 파일 이름에 못 쓰는 `/`·`:`는 `-`로 바꾼다. `title`이 비어 있으면 상호·주제로 짧게 짓는다.
- 사진: `jpg/jpeg/png/heic/webp/gif` (대소문자 무관). 사진이 0장이어도 글은 쓴다.
- 그 밖의 파일(`.DS_Store`, `.gitkeep` 등)은 무시하고 옮기지 않는다.

입력 `.md`는 사용자가 **직접 쓰는 블로그**의 재료다. frontmatter에는 `title`(가제)과 `category`(네이버 블로그 카테고리 이름, 예: 일상·맛집 리뷰·제품 리뷰)만 있다(둘 다 없어도 된다). 본문은 `templates/topic.md`의 칸(주제, 꼭 전하고 싶은 것, 내 경험, 메모, 참고 글)으로 되어 있다.

문체·분량·태그·장소 등은 입력에서 받지 않고 Claude가 정한다:

| 항목 | 정하는 법 |
|---|---|
| 제목 | `title`을 가제로 삼아 기준 가이드(`templates/네이버 블로그 맛집 포스팅 작성 가이드.md`)의 제목 규칙(지역 + 상호 + 대표 메뉴 + (메뉴·가격))에 맞게 다듬는다. 없으면 주제에서 만든다 |
| 문체·구조·분량 | 기준 가이드의 섹션 표·문체 규칙·이모티콘 규칙을 따른다 |
| 카테고리 | 입력 `.md`의 `category`를 원고 frontmatter `category`로 그대로 옮긴다. 비어 있으면 넣지 않는다(블로그 기본 카테고리) |
| 태그 | 10~15개를 골라 원고 frontmatter `tags`에 적는다(띄어쓰기 없이). 상호, `지역+업종`(수원맛집), 쇼핑몰·동네+업종(스타필드수원맛집), 메뉴(육개장맛집, 가브리살수육), 상황(퇴근후저녁) 순으로 섞는다. 같은 뜻의 검색어 변형(수원스타필드맛집/스타필드수원맛집)은 둘 다 넣어도 된다. 발행 설정 창에 자동으로 들어간다(B-5) |
| 장소 지도 | 가게·장소 후기면 `.md`의 상호·지역으로 검색어를 만들어 원고 frontmatter `place`와 본문 `[[장소: 검색어]]`에 쓴다. 검색어는 `상호 + 시/구`(예: `육당헌 수원`)가 잘 잡힌다. 쇼핑몰 이름을 붙이면(`육당헌 스타필드 수원`) 결과가 없을 수 있어, 입력 코드는 뒤 단어를 빼며 다시 찾는다. 상호를 모르면 넣지 않는다. 찾은 주소(층 포함)는 기본정보에 써도 된다 |
| 정렬 | 왼쪽(기본). 사용자가 가운데 정렬을 요청할 때만 원고 frontmatter에 `align: center` |

## 진행 방식 (2026-11-07 기준)

1. 먼저 `inputs/result.md`에(제목·카테고리·태그 + 본문 + `📷 [사진] 파일명 — 설명` 자리 + `[지도]` 자리 + 쓰지 않은 사진 표)를 쓰고 사용자에게 보여 준다.
2. 사용자가 고칠 점을 말하면 result.md를 고친다. 사용자가 네이버 플레이스 링크를 주면 주소·영업시간·주차·편의 정보를 읽어 정보 블록에 넣는다.
3. 사용자가 "작성해줘"라고 하면 result.md를 `drafts/draft.md`로 옮긴다(`────`→`---`, 사진 줄→`![설명](images/pNN.jpg)` + `sips`로 축소 복사, `[지도]`→`[[장소: 검색어 | 주소 일부]]`). 그 다음 B(네이버 입력·카테고리·태그·임시저장)와 C(done 이동)를 한다.

## A. 중간 원고 작성 (drafts/, 네이버에 넣기 전 작업본)

`drafts/draft.md`가 이미 있으면(지난번 임시저장이 실패한 경우) 새로 쓰지 않고 그 원고를 그대로 B로 넘긴다. 사용자가 다시 쓰라고 하면 그때만 새로 쓴다.

1. **읽기**
   - `.md` 파일을 읽고 frontmatter와 본문(주제, 내 경험, 메모, 붙여 둔 참고 글)을 파악한다.
   - 폴더 안의 사진을 모두 **직접 보고** 각 사진에 무엇이 찍혔는지 파악한다. 원본이 크면 `sips -Z 700 <원본> --out <scratchpad>/NN.jpg`로 줄여서 본다(HEIC도 이걸로 변환된다). 메뉴판·안내문처럼 글씨가 중요한 사진은 `sips -Z 1900`으로 크게 보고 필요한 부분만 `sips -c`로 잘라 읽는다.
   - 촬영 시각이 흐름에 도움이 되면 `mdls -name kMDItemContentCreationDate <파일>`로 확인한다(UTC로 나오므로 한국 시간은 +9시간).

2. **구성 잡기** — 아래 "글쓰기 기준"을 따른다.
   - 사진을 기준 가이드의 "사진 촬영·배치 가이드" 위치에 맞춰 섹션에 배치한다(섹션당 1~2장, 비슷한 컷은 한 장만). 흐름에 맞지 않거나 중복된 사진은 빼되 보고에 알린다.
   - **개인정보가 보이는 사진은 뺀다**: 차량 번호판이 읽히는 사진, 모르는 사람(특히 아이)이 크게·정면으로 찍힌 사진, 카드 번호·영수증 개인정보. 빼기 아까운 사진은 넣고 보고에 "N번 사진 얼굴 모자이크 필요"라고 적는다.
   - `.md`에 붙여 둔 참고 글은 그대로 베끼지 말고 요약·재서술해 녹인다. 직접 인용은 짧게, 출처를 밝힌다.

3. **쓰기** — `drafts/draft.md`
   - 사진은 `sips -Z 2000 -s format jpeg -s formatOptions 85 <원본> --out drafts/images/NN.jpg`로 줄여 복사하고 상대 경로 `images/NN.jpg`로 넣는다(업로드가 빨라지고 HEIC도 jpg가 된다).
   - 네이버 에디터로 옮길 수 있는 문법만 쓴다. `scripts/md_to_blocks.py`가 이렇게 바꾼다:

     | 원고 문법 | 에디터 |
     |---|---|
     | `# 제목` | 제목 칸(frontmatter `title`이 우선) |
     | `## 소제목` | 소제목 |
     | 연속된 줄 | 한 줄씩 그대로(줄바꿈 유지) |
     | 빈 줄 | 문단 사이 빈 줄 |
     | `- 항목` | 글머리 목록 |
     | `> 문장` | 인용구 |
     | `---` | 구분선 |
     | `[[장소: 검색어]]` | 네이버 장소 지도 |
     | `[[장소: 검색어 \| 주소 일부]]` | 결과 중 주소가 맞는 곳만 고름(상호가 "우동집"처럼 흔할 때) |
     | `![설명](images/NN.jpg)` | 사진 |
     | 사진 바로 다음 줄 `*캡션*` | 사진 캡션(선택) |
     | `<!-- ... -->` | 올라가지 않음(Claude 메모용. 사용자에게 알릴 것은 보고에 쓴다) |

   - 표·코드블록·중첩 목록·굵게·링크 문법은 쓰지 않는다(에디터에서 렌더링되지 않는다).
   - 소제목은 `## ` 처럼 `#` 뒤에 공백이 있을 때만 된다. `#메가커피 #태그`처럼 붙여 쓴 해시태그 줄은 본문으로 들어간다.
   - 본문에 쓴 `#단어`는 네이버가 **태그로 자동 등록**한다. `단서 #1은`처럼 태그가 되면 안 되는 `#`은 피한다(→ "첫 번째 단서는"). 넣은 뒤 B-5 반환값 `tags`에 엉뚱한 태그가 있는지 본다.
   - 사진·`.md`에 없는 구체적 사실(가격, 지명, 맛, 동행인, 날짜, 웨이팅, 주차 조건 등)을 **지어내지 않는다**. 모르는 항목은 기준 가이드대로 **그 문장을 빼고**, 빈칸·`[ ]`·TODO를 본문에 남기지 않는다. 빠진 정보는 채팅 보고에 "`.md`에 적어 주면 들어갈 정보"로 알린다. 사진 속 메뉴판·안내문에서 읽은 내용은 "방문 당시 기준"이라고 밝힌다.

### 글쓰기 기준

**기준 문서: `templates/네이버 블로그 맛집 포스팅 작성 가이드.md`** (사용자가 직접 쓴 가이드). 원고를 쓰기 전에 **매번 이 파일을 읽고** 그대로 따른다. 아래 규칙과 부딪히면 기준 가이드가 우선이다.

- **맛집 글**(카테고리 `맛집`이거나 식당·음식 후기): 기준 가이드 전체(섹션 구조 9단계, 사진 배치, 문체, 이모티콘, 정보 체크리스트, 맛 묘사 4단계, 하지 말아야 할 것, Before/After)를 적용한다.
- **맛집이 아닌 글**(카페·여행·일상·리뷰): 문체 규칙, 이모티콘 규칙, 줄바꿈, "하지 말아야 할 것"은 그대로 따르고, 섹션 구조·체크리스트·맛 묘사는 주제에 맞게 바꿔 쓴다(예: 메뉴별 리뷰 → 공간별·코스별 리뷰).
- 쓰고 나서 기준 가이드의 **"발행 전 셀프 체크"**를 원고에 대고 하나씩 확인하고, 아니오인 항목을 고친다. 정보가 없어서 못 채운 항목(총 결제 금액, 웨이팅, 주차 등)은 보고에 적는다.

기준 가이드보다 우선하는 사용자 피드백 (2026-11-06~07). 문체는 `templates/맛집 블로그 문체 분석.md`도 함께 읽는다:
- **말투는 친근한 존댓말** (2026-11-07 최종). 기본 `~요`(`~더라고요`, `~거든요`, `~하시면 돼요`), 가끔 `~습니다`로 끝을 바꿔 준다. 독자에게는 `~하세요`, `가시면`. 30대 기혼 남자 화자(`저희는`, `와이프랑`). 이모지는 정보 블록 아이콘 외엔 거의 안 쓰고, `ㅋㅋ`·`ㅎㅎ`·`ㅠ`는 글 전체에 한 번씩 정도. 기준 가이드의 어미 비율·이모티콘 규칙 대신 이것을 따른다.
- **정보 전달 우선** (2026-11-07). 감상보다 독자가 갈 때 필요한 정보를 먼저, 많이 쓴다. 순서: `> ○○ 한눈에 보기`(총 결제·한 줄 평·방문 시간/웨이팅 ✔️ 3줄) → `> 메뉴·가격`(메뉴판에서 읽은 메뉴별 단품/세트 가격을 `*` 목록으로, 세트 추가금·구성) → `> 주문 방법`(키오스크·테이블오더·이벤트) → `> 세트 구성`(나오는 것 개수까지 목록) → `> 좌석·분위기`(좌석 수 목록, 혼밥·단체 가능 여부) → 메뉴별 후기(짧게) → `> 이런 분께`(✔️ 상황별 추천·주의). 감상 문장은 메뉴 후기 섹션에 2~4줄로 줄인다. 메뉴판에서 확실히 읽은 가격만 쓰고, 안 읽히는 건 "메뉴판에서 확인"으로.
- **구성은 `templates/맛집 블로그 문체 분석.md`의 "30대 남자 버전" 규칙 11개를 따른다** (사용자가 고른 리뷰 4개의 장점만 모은 것, 2026-11-07):
  - 맨 위 인용구 라벨(`> 추운 날 점심, 흥덕 우동집`) → 오늘 상황(블로그 정체성·자기소개 문구는 넣지 않는다) → 미리보기(결론 + 반전 예고).
  - 정보 블록은 인용구 라벨(`> ○○ 정보`) 아래 아이콘 줄: 📍위치 ⏰영업시간 🅿️주차 💳총 결제 🍜메뉴·가격 🕚방문·웨이팅 ✔️세트 구성·팁. 모르는 줄은 뺀다. 아이콘은 여기에만.
  - 섹션 라벨은 인용구 한 줄(`> 얼큰 우동`, `> MENU | 둘 다 얼큰 우동 세트`, `> INTERIOR | 아담한 가게`). 정식 소제목(`##`)은 쓰지 않는다. 섹션 사이 `---`.
  - 사진 1장 + 1~2줄 리듬. 과정·결과 컷은 한 줄로 툭("결국 이렇게 됐어 ㅋㅋ").
  - 메뉴마다 메뉴명 + 한 줄 평 + 먹는 법·조합, 실전 팁(주문 방식, 시간대, 이벤트), 단점은 누구에게 아쉬운지까지.
  - 마무리 = 가격 대비 + 누구랑/언제 가면 좋은지 + 다음 계획.
  - 정보 블록에 쓴 내용(가격, 주문 방식, 이벤트)은 본문·마무리에서 다시 나열하지 않는다.
- **사람 글처럼 (AI 티 없애기)**:
  - 첫 줄은 그날 왜 거기 갔는지를 사적으로(요일·날씨·동행·오랜만인지).
  - 메뉴마다 '내 기준' 한 줄: 예전엔 어땠는지, 원래 뭘 시키는지.
  - 형용사 대신 숫자·개수·비교(유부초밥 2개, 튀김 4조각, 바 5~6석).
  - 줄 길이를 일부러 섞는다. 한두 단어 줄("얼큰 우동.", "주문은 키오스크.")을 군데군데.
  - 금지: "~느낌", "사르르", "결론부터 말하면", "자 이제", 세 개씩 나열(메뉴·반찬 목록 제외), 섹션마다 고르게 배치된 이모지, 정중하게 대칭으로 쓴 부정.
  - 부정은 짧고 직설적으로("이것도 예전보다는 아쉬웠다."). 마무리는 다음 계획 한 줄로.
  - 대화·감정·딴소리는 지어내지 않는다. '내 경험'·메모·사진에 있는 범위에서만 말투를 바꿔 쓴다. 경험보다 세게 쓰지 않는다("좀 작아짐"을 "확실히 작아짐"으로 쓰지 않기).

기준 가이드에 없는, 이 프로젝트에서 따로 정한 규칙:
- **지어내지 않기**: 맛·양·가격·동행·대기·분위기 같은 경험은 `.md`의 '내 경험'과 사진에서 확인되는 것만 쓴다. 맛 묘사 4단계(첫 입·감각·비교·양)를 채울 재료가 없으면 그 단계 문장은 빼고 보고에 알린다.
- **아쉬운 점**: 기준 가이드대로 **글마다 하나 이상** 쓴다. '내 경험'의 아쉬운 점을 먼저 쓰고, 비어 있으면 사진·메뉴판·메모로 확인되는 것(가격 대비 양, 자리 간격, 대기, 주차 등 가이드의 후보) 중에서 하나를 고른다. 확인되는 게 없으면 지어내지 말고 섹션을 빼고 보고에 "아쉬운 점을 적어 주세요"라고 알린다.
- **같은 정보 반복 금지**: 한 번 쓴 정보(가격, 메뉴 목록, 주소, 같은 감상 표현)는 다른 섹션에서 다시 나열하지 않는다. 기본정보에 가격을 썼으면 "주문은 이렇게"·메뉴 리뷰에서는 가격 목록을 또 쓰지 않는다. 다 쓴 뒤 섹션끼리 겹치는 문장·표현을 한 번 훑는다.
- **장소 지도**: 상호를 알면 기본정보 블록 바로 아래 `[[장소: 검색어]]`. 한 번만.
- **소제목 이모티콘**: 기준 가이드대로 소제목 앞에 붙인다(`## 📍 기본정보`). 입력 코드가 이모지를 따로 넣으므로 그대로 써도 된다.
- **AI 티 나는 표현 금지**: "~할 수 있습니다", "다양한", "완벽한", "결론적으로", "한마디로", 세 가지씩 나열하는 습관.
- 원고 frontmatter 예시:

  ```markdown
  ---
  title: 수원 스타필드 육당헌 | 사골 육개장·된장 가브리살 수육 (메뉴·가격)
  date: 2026-11-06
  category: 맛집
  tags: [육당헌, 스타필드수원, 수원스타필드맛집, 스타필드수원맛집, 수원맛집, 육개장맛집, 가브리살수육]
  place: 육당헌 수원
  ---
  ```

## B. 네이버 블로그 임시저장 (Playwright MCP)

`mcp__playwright__*` 도구를 쓴다. 도구가 로드되지 않았으면 ToolSearch로 먼저 로드한다. 페이지 구조가 바뀌어 아래 방법이 안 되면 `browser_snapshot`(길면 `filename`으로 저장 후 grep)으로 요소를 다시 찾는다.

### B-1. 입력 코드 만들기

```bash
python3 scripts/md_to_blocks.py drafts/draft.md > <scratchpad>/blocks.json
python3 scripts/naver_segments.py <scratchpad>/blocks.json <작업폴더>/.playwright-mcp/seg-<이름>
```

- 두 번째 출력 폴더는 **Claude Code 작업 폴더 아래**여야 한다(`browser_run_code_unsafe`의 `filename`과 `browser_file_upload`는 작업 폴더 밖 파일을 못 읽는다). `.playwright-mcp/`는 gitignore 대상이다.
- 출력되는 `plan.json`이 실행 순서다: `00-title.js` → 구간별 `NN-text.js` 또는 사진 3단계(`NN-goto.js` → `browser_file_upload(path)` → `NN-cap.js`).
- `filename`의 상대 경로는 Playwright MCP 루트(Claude Code를 처음 연 폴더) 기준이다. 헷갈리면 절대 경로를 쓴다.
- 같은 폴더에 다시 생성할 때는 지우지 말고 그냥 덮어쓴다(`rm`은 안전 검사에 막힐 수 있다).

### B-2. Google → 네이버 → 로그인 확인

1. `browser_navigate`로 `https://www.google.com` 을 연다.
2. 검색창에 `네이버`를 입력하고 검색 결과의 링크 "네이버 NAVER https://www.naver.com" 을 클릭한다. 한 번에:
   ```js
   async (page) => { const box = page.getByRole('combobox', { name: '검색' }); await box.fill('네이버'); await box.press('Enter'); await page.waitForLoadState('domcontentloaded'); const link = page.getByRole('link', { name: /네이버 NAVER https:\/\/www\.naver\.com/ }).first(); await link.waitFor({timeout: 10000}); await link.click(); await page.waitForURL(/naver\.com/); return (await page.context().cookies('https://www.naver.com')).some(c => c.name === 'NID_AUT'); }
   ```
   - "비정상적인 트래픽"·reCAPTCHA 화면이 나오면 **풀지 말고** 사용자에게 Playwright 창에서 직접 풀어 달라고 하고, 검색 결과가 뜰 때까지 기다린다.
3. 반환값(`NID_AUT` 쿠키 여부)이 `true`면 B-3으로. `false`면 메인의 링크 "NAVER 로그인"을 클릭하고 `page.bringToFront()`로 창을 앞으로 띄운다.
4. **ID·비밀번호는 Claude가 입력하지 않는다.** 계정 정보를 채팅으로 받아도 쓰지 않는다. 사용자에게 이렇게 알린다:
   > Playwright 크롬 창("Chrome이 자동화된 테스트 소프트웨어에 의해 제어되고 있습니다" 표시가 있는 창)에서 직접 로그인해 주세요. "로그인 상태 유지"를 체크하면 다음부터는 이 단계가 생략됩니다.

   그 다음 아래 코드로 `NID_AUT` 쿠키가 생길 때까지 최대 5분 기다린다. 시간이 지나도 안 생기면 사용자에게 다시 묻는다.
   ```js
   async (page) => { const t = Date.now(); while (Date.now() - t < 290000) { if ((await page.context().cookies('https://www.naver.com')).some(c => c.name === 'NID_AUT')) return true; await page.waitForTimeout(3000); } return false; }
   ```

### B-3. 블로그 → 글쓰기

1. 지난 실행에서 남은 탭이 있으면 먼저 닫는다(`browser_tabs` close). 글쓰기 탭을 떠날 때 "beforeunload" 확인 창이 뜨면 `browser_handle_dialog(accept: true)`.
2. naver.com 에서 "블로그" → 새 탭(블로그 홈) → "글쓰기" → 또 새 탭이 열린다. 한 번에:
   ```js
   async (page) => { const ctx = page.context(); const [blog] = await Promise.all([ctx.waitForEvent('page'), page.getByRole('link', { name: '블로그', exact: true }).first().click()]); await blog.waitForLoadState('domcontentloaded'); const [editor] = await Promise.all([ctx.waitForEvent('page'), blog.getByRole('link', { name: '글쓰기' }).first().click()]); await editor.waitForLoadState('domcontentloaded'); await editor.waitForTimeout(5000); return ctx.pages().map(p => p.url()); }
   ```
3. `browser_tabs` select로 **글쓰기 탭**(`blog.naver.com/<블로그ID>?Redirect=Write`)을 고른다. 이후 모든 코드는 이 탭에서 돈다. 에디터는 `mainFrame` iframe 안에 있다.
4. `00-title.js`를 실행한다. "작성 중인 글이 있습니다" 팝업을 **취소**하고 제목을 넣은 뒤, 시작 전 임시글 개수(`count`)를 돌려준다. 이 값을 기록해 둔다.

### B-4. 내용 입력

`plan.json` 순서대로 실행한다. 각 코드는 마지막 컴포넌트 4개를 돌려주므로 매번 의도대로 쌓였는지 본다.

- **글 구간**: `browser_run_code_unsafe(filename: ".../NN-text.js")`. 반환값의 `warn`에 장소 검색 결과가 찍힌다. **장소 결과가 원하는 가게가 아니면**(이름·지역이 다름) 그 지도 컴포넌트를 지우고 보고에 적는다.
- **사진 구간** — 세 호출을 한 메시지에 순서대로 보내도 된다:
  1. `NN-goto.js` → 파일 선택 모달이 뜬다(run_code 안에서 `waitForEvent('filechooser')`를 쓰면 MCP가 먼저 가로채서 안 된다).
  2. `browser_file_upload(paths: [path])` — 작업 폴더 아래 절대 경로만 된다.
  3. `NN-cap.js` → 업로드 완료(`img src`가 `blogfiles.pstatic.net`)를 기다린 뒤 캡션이 있으면 넣는다.
- 첫 사진은 자동으로 "대표" 사진이 된다. 사진을 올리면 오른쪽에 "라이브러리" 패널이 열리지만 입력에는 지장이 없다.
- 글쓰기 탭이 갑자기 닫히면 B-3부터 다시 한다(이미 넣은 내용은 자동저장에 남지만 불러오지 말고 새로 쓴다).

검증된 에디터 조작(코드 생성기가 쓰는 방법, 페이지가 바뀌었을 때 참고):

| 블록 | 방법 | 결과 컴포넌트 |
|---|---|---|
| 제목 | `.se-documentTitle .se-text-paragraph` 클릭 → type | `se-documentTitle` |
| 문단 줄 | type → `Enter` (줄마다) / 문단 끝에 `Enter` 한 번 더 | `se-text` |
| 이모지 | `keyboard.type`은 `✔️`·`☁️`처럼 FE0F가 붙은 이모지를 "✔✔️"로 두 번 찍는다. 이모지 부분만 `keyboard.insertText`로 넣는다(문장 전체를 `insertText`로 넣으면 일부가 사라진다) | |
| 소제목 | "문단 서식 변경" → `button.__se-sentry` "소제목" → type → `Enter`(자동으로 본문 복귀) | `se-sectionTitle` |
| 목록 | "목록 열기" → "기호목록" → 항목마다 type+`Enter` → `Enter` 한 번 더(빠져나옴) | `se-text` 안 `ul` |
| 인용구 | "인용구 추가" → 800ms → type → 아래 빈 곳 클릭으로 빠져나옴 | `se-quotation` |
| 구분선 | "구분선 추가" (뒤에 본문 칸 자동 생성) | `se-horizontalLine` |
| 장소 | "장소 추가" → `input[placeholder="장소명을 입력하세요."]` → "검색" → 결과에 **마우스를 올려야** 보이는 `.se-place-add-button` → `.se-popup-button-confirm` | `se-placesMap` |
| 정렬 | "정렬 열기" → "가운데 정렬" 등 | 문단 `align-center` |
| 사진 캡션 | 사진 `img`를 **먼저 클릭해야** `.se-caption .se-text-paragraph`가 보임 | |
| 끝으로 이동 | 마지막이 `se-text`면 그 마지막 줄 클릭+`End`, 아니면 마지막 컴포넌트 아래 25px 클릭 | |

**카테고리·태그**: 에디터가 아니라 "발행" 설정 창에 있다. 본문을 다 넣은 뒤 B-5에서 `99-publish-settings.js`로 넣는다.

**최종 점검**: 다 넣은 뒤 컴포넌트를 세어 원고와 맞춰 본다(제목, 소제목 목록, 사진 수, 빈 캡션 수, 장소 지도 유무). 화면 밖 사진은 지연 로딩이라 `src`가 `data:image/svg`로 보일 수 있다. `scrollIntoViewIfNeeded()` 후 다시 확인한다.

### B-5. 카테고리·태그 넣고 임시저장

0. **카테고리·태그**: `99-publish-settings.js`를 실행한다.
   - 상단 "발행" 버튼은 **설정 창만 연다**. 창 안 맨 아래의 최종 "발행" 버튼(`button[class^=confirm_btn]`)은 **절대 누르지 않는다**. 코드도 누르지 않는다.
   - 카테고리를 고르면 "주제"도 자동으로 같이 바뀐다. 기본으로 `#첫글` 같은 태그가 미리 들어 있을 수 있는데 지우지 않는다.
   - 반환값 확인: `category`가 원하는 이름인지, `tags`에 넣은 태그가 다 있는지, `layerClosed`가 `true`인지(Esc로 창이 닫혀야 다음 단계 버튼을 누를 수 있다), `warn`에 "카테고리 없음"이 없는지. 카테고리가 없으면 보고에 실제 목록과 함께 적는다.
   - 확인된 동작: 설정 창을 닫았다 다시 열어도 카테고리·태그가 남아 있다. 임시저장 후 다시 불러왔을 때도 남는지는 아직 확인하지 못했다. 첫 실행 때 보고에 적고, 사용자가 확인하게 한다.
1. **"저장" 버튼만** 누른다. **"발행" 버튼은 어떤 경우에도 누르지 않는다.**
   ```js
   async (page) => { const f = page.frame('mainFrame'); const cnt = f.locator('button[class^=save_count_btn]'); const before = await cnt.innerText(); await f.locator('button[class^=save_btn]').click(); let toast = ''; for (let i = 0; i < 20 && !toast.includes('임시저장'); i++) { await page.waitForTimeout(500); toast = await f.evaluate(() => [...document.querySelectorAll('[class*=toast], [class*=noti], [role=alert]')].filter(e => e.offsetParent).map(e => e.innerText).join(' | ')); } await page.waitForTimeout(1500); return {before, after: await cnt.innerText(), toast: toast.split(' | ')[0]}; }
   ```
2. 성공 조건 두 가지를 모두 확인한다.
   - 알림 "임시저장이 완료되었습니다."가 뜬다.
   - 임시글 숫자가 B-3-4에서 기록한 값보다 1 늘었다.
3. 실패하거나 확인이 안 되면 C로 가지 말고, `inputs/`, `drafts/`를 그대로 둔 채 이유를 보고한다(다음 실행 때 같은 원고로 다시 시도된다).
4. 여러 건을 처리할 때는 다음 건마다 B-3(블로그 홈 → 글쓰기)부터 다시 한다. 쓰던 글쓰기 탭은 닫는다.

### B-6. 이미 저장한 임시글 고치기 (사용자 피드백 반영 등)

- 사진 편집(기울기·비율)은 **사용자가 직접** 한다. Claude는 사진 편집기를 건드리지 않는다.
- 사용자가 브라우저에서 직접 고친 내용이 있을 수 있으니 **글쓰기 탭을 새로 고치지 말고** 지금 상태를 먼저 읽는다.
- 한 줄 바꾸기: 그 줄(`.se-text-paragraph`)을 클릭 → `End` → 줄 글자 수(`Intl.Segmenter`로 센 grapheme 수)만큼 `Backspace` → 줄이 비었는지 확인 → 새 문장 입력(이모지는 `insertText`). 줄이 화면에서 두 줄로 넘어가면 한 번에 다 안 지워지니 확인 후 남은 만큼 더 지운다.
  - 세 번 클릭(줄 선택)이나 DOM `Range` 선택 후 입력은 **안 된다**(에디터가 자체 선택 상태를 써서 글자가 붙는다).
- **커서 이동 주의**(2026-11-11): 방향키(`ArrowLeft/Right`)는 에디터에서 먹지 않는다. 가운데 정렬 줄을 가운데로 클릭하면 커서가 줄 중간에 놓이거나 단어가 선택돼 `Enter`가 글자를 지운다. 줄 **맨 앞**은 `click({force: true, position: {x: 2, y: 8}})` → `Home`, 줄 **맨 끝**은 줄 상자 오른쪽 끝(`b.x + b.width - 3`)을 `page.mouse.click`. 두 줄 합치기는 맨 앞 클릭 → `Home` → `Backspace`. 키 입력 사이에 100~150ms씩 쉬고, 매 단계 문단 목록(`allInnerTexts`)으로 확인한다.
- 줄 지우기: 위 방법으로 비운 뒤 `Backspace` 한 번 더(윗줄과 합쳐짐).
- 섹션 지우기: 구분선·사진은 클릭하면 나오는 `button.se-delete-toolbar-button`으로, 소제목·본문은 글자를 다 지운 뒤 빈 소제목에서 `Backspace` 한 번. 매 단계 컴포넌트 목록을 다시 읽어 주변이 지워지지 않았는지 본다.
- 사진 바꾸기: 바꿀 사진 `img`를 클릭(선택) → "사진 추가" → `browser_file_upload` 하면 **선택한 사진 바로 뒤에** 들어간다. 새 사진이 들어간 걸 확인한 뒤 옛 사진을 클릭 → `button.se-delete-toolbar-button:visible`로 지운다. 첫 사진을 지우면 새 사진이 자동으로 대표가 된다.
  - 화면 밖 사진은 `src`가 늦게 로딩돼 파일명으로 못 찾는다. 먼저 사진마다 `scrollIntoViewIfNeeded()`로 순서·파일명을 확인하고 `nth(i)`로 고른다. 여러 장이면 뒤쪽부터 바꿔야 번호가 안 밀린다.
- 문장 뒤에 사진 넣기: 그 줄을 클릭 → `End` → "사진 추가". 같은 호출에서 `Enter` 후 새 문장을 치고 바로 "사진 추가"를 누르면 글자가 사진 앞뒤로 쪼개질 수 있으니, 문장 입력과 사진 추가는 따로 하고 매번 결과를 확인한다.
- **예약 발행 글**(상단에 "예약 발행 1건")은 "저장" 버튼이 동작하지 않는다(알림 없음). 수정 내용은 "발행 → 예약 확인"으로만 반영되므로 Claude는 거기서 멈추고 사용자에게 직접 누르게 한다.
- 저장은 B-5와 같다. 기존 임시글을 덮어쓰는 것이라 **임시글 숫자는 늘지 않는다**. 알림 "임시저장이 완료되었습니다."로 성공을 판단한다.

## C. 완료 정리

B-5가 성공한 건만 옮긴다. 사진이 두 번 남지 않게 **원본 사진만** 보관하고, `drafts/images/`의 축소 사본과 `result.md`는 남기지 않는다.

```bash
dest="done/<제목>"
mkdir -p "$dest"
mv inputs/topic.md drafts/draft.md "$dest/"
find inputs -maxdepth 1 -type f -iregex '.*\.\(jpe?g\|png\|heic\|webp\|gif\)' -exec mv {} "$dest/" \;
rm -r drafts/images inputs/result.md        # 축소 사본·검토용 원고 (막히면 남겨 두고 보고)
cp templates/topic.md inputs/topic.md       # 다음 건용 빈 양식
```

`$dest`가 이미 있으면 ` (2)`, ` (3)`을 붙인다. `done/`은 gitignore 대상이라 GitHub에 올라가지 않는다. 옮긴 뒤 `inputs/`에 빈 `topic.md`만, `drafts/`에는 `.gitkeep`만 남았는지 확인한다.

입력 코드 폴더(`.playwright-mcp/seg-<이름>`)는 작업 폴더 안이라 `rm -rf`가 안전 검사에 막힐 수 있다. 막히면 지우지 말고 보고에 남긴다.

## 보고

처리한 건마다 채팅에 짧게:
- 결과: 임시저장 완료(→ `done/<제목>/`) / 실패(이유, 남겨둔 위치)
- 제목 후보 2~3개
- 쓰지 않은 사진과 이유, 모자이크가 필요한 사진
